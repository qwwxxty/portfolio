# VIDEOS — что снять для слотов

На сайте два вида видео:

1. **Готовые рилсы** (уже есть, показываются сразу): `assets/media/reels/*.mp4` — плеер со звуком; `assets/media/previews/*.mp4` — 6-секундные беззвучные превью, которые играют внутри стеклянных карточек сцены 02 и на мониторе сцены 04; `assets/media/compare/*.mp4` — слайдер сравнения в сцене 03. Их не трогаем.
2. **Новые слоты сцен** в `assets/videos/`. Пока файлов нет, в слотах работает графика из кода (туманность, частицы, лента плёнки), а запросов к несуществующим файлам нет вообще: статус слота задаётся конфигом `VIDEO_SLOTS` в начале `script.js`.

## Слоты

| Слот | Файлы | Где на сайте | Как ведёт себя | Пока видео нет |
|---|---|---|---|---|
| `hero` | `assets/videos/hero.mp4` + `hero.webm` | фон сцены 01 Slate, за частицами имени | петля, без звука, гаснет при уходе со сцены | туманность из шума + частицы |
| `scrub` | `assets/videos/scrub.mp4` + `scrub.webm` | фон сцены 04 Layers, за монитором и дорожками | **крутится скроллом**: позиция в видео = прогресс сцены | вертикальная лента плёнки с перфорацией, кадры едут со скроллом |
| `export` | `assets/videos/export.mp4` + `export.webm` | фон сцены 06 Export, за кольцом лидера | петля, без звука | туманность + кольцо из частиц |

Видео во всех слотах автоматически приглушается и тонируется в палитру сайта (холодная бирюза + тёплый свет), поэтому снимать лучше тёмные, контрастные кадры с одним источником света — яркий «плоский» материал превратится в серую кашу.

## Что снять

### `hero` — «монтажная ночью»
- **Сюжет:** макро монтажного стола в темноте: свет монитора на клавиатуре и джог-колесе, по экрану бежит таймлайн, плейхед движется слева направо; можно руки на клавиатуре в силуэте. Альтернатива: макро дыма/пыли в луче проектора.
- **Свет:** один холодный источник (монитор) + тёплый контровой (лампа или красный LED) — это и есть палитра сайта.
- **Движение:** медленное, без резких склеек; камера на штативе или очень плавный слайдер.
- **Длительность:** 8–12 с, петля без шва (начало и конец похожи по свету).
- **Кадр:** горизонтальное 16:9, 1920×1080 (4K можно — скрипт уменьшит). На телефонах видео обрезается по центру до вертикали, поэтому главное держите в центральной трети кадра.

### `scrub` — «кадр, который собирается слоями»
- **Сюжет:** один и тот же кадр говорящей головы, на который по очереди «ложатся» слои: сырой кадр → графика → субтитры → грейд. Это продолжает текст сцены 04 (The first second → Graphics that explain → Captions with rhythm → A look for each story). Подойдёт экранная запись вашего проекта в монтажке, где включаются дорожки V1–V4.
- **Движение:** плавное и непрерывное — видео прокручивается скроллом вперёд и назад, резкие склейки будут дёргаться.
- **Длительность:** 4–6 с (весь скролл сцены 04 — это эти секунды).
- **Кадр:** горизонтальное 16:9, 1280×720 достаточно: файл кодируется так, что каждый кадр ключевой (all-intra), иначе перемотка скроллом рывками.

### `export` — «экспорт готов»
- **Сюжет:** макро прогресс-бара рендера/экспорта на мониторе, отражение экрана в глазах или очках, свет от экрана на лице в темноте; или лидер плёнки с обратным отсчётом, снятый на настоящем проекторе.
- **Длительность:** 8–12 с, петля.
- **Кадр:** горизонтальное 16:9, 1920×1080, главное в центре (на телефоне по центру обрезается).

## Требования к файлам

- MP4 (H.264, `yuv420p`, `+faststart`) **и** WebM (VP9) — сайт выберет WebM, если браузер его поддерживает.
- Без звука, не больше 1080p (`scrub` — 720p), **не больше 4 МБ на файл**.
- Для `scrub` ключевой кадр на каждом кадре.

Всё это делает `encode.sh` (нужен ffmpeg с libx264 и libvpx-vp9):

```bash
./encode.sh hero   ~/Footage/desk-night.mov
./encode.sh scrub  ~/Footage/layers-build.mov
./encode.sh export ~/Footage/export-bar.mov
```

Скрипт обрезает клип до 12 с (`scrub` — до 6 с; третий аргумент меняет лимит), считает битрейт от длины, кодирует в два прохода, а если файл всё равно больше 4 МБ — перекодирует с меньшим битрейтом. Для `scrub` в конце печатает «keyframes: N of N frames».

## Как включить слот

В начале `script.js`:

```js
const VIDEO_SLOTS = {
  hero:   { ready: true,  ... },   // было false
  scrub:  { ready: false, ... },
  export: { ready: false, ... },
};
```

Пока `ready: false`, сайт не делает ни одного запроса к `assets/videos/`, поэтому в консоли нет 404. Видео слотов грузятся лениво — только когда их сцена рядом, и не входят в первую загрузку.

## Проверено

`encode.sh` прогнан в этом окружении (ffmpeg 6.1.1) на синтетическом 1080p-клипе с шумом (худший случай для сжатия) и на реальном ролике `compare/gold.mp4`: `hero` 3746 КБ / 3599 КБ, `scrub` 3731 КБ / 3530 КБ (WebM ушёл на второй проход с меньшим битрейтом), `export` 3724 КБ / 3788 КБ; у `scrub.mp4` 144 ключевых кадра из 144. Закодированные тестовые файлы подставлялись в браузере во все три слота — видео появляется в своих сценах, ошибок в консоли нет. В репозиторий тестовые файлы не добавлены.
